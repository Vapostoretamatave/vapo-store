# VAPO STORE TAMATAVE — Mémoire du projet

Boutique vape en ligne + section admin. Node.js pur (aucun framework), stockage = fichiers JSON dans `data/`, uploads images dans `public/uploads/`.

## Démarrer (local)
- Lancer **DEMARRER.bat** (démarre `node server.js` sur port 3000).
- Node : `C:\Program Files\nodejs\node.exe`.
- Boutique : `http://localhost:3000` · Admin : `http://localhost:3000/admin`.
- **Admin password : `vapostore2026`** (stocké dans `data/settings.json`).
- ⚠️ Aucun serveur ne doit tourner au moment d'une modification : après chaque modif l'utilisateur relance DEMARRER.bat. Un process node lancé pour test doit être arrêté (`Stop-Process`).
- Vérif syntaxe : `node --check server.js` / `node --check public\app.js` / `node --check admin\admin.js`.

## Technique anti-cache (IMPORTANT)
- `public/index.html` référence `/app.vN.js` et `/styles.css?v=N`.
- `admin/index.html` référence `/admin/admin.vN.js` et `/admin/admin.css?v=N`.
- **Règle** : quand on modifie `public/app.js`, bump vers app.v(N+1) et copier LA SOURCE sur TOUTES les versions numérotées (v5..N+1). Idem admin. Quand on modifie un CSS, bumper son `?v=`.
- État actuel (à mettre à jour) : boutique = app.v52.js + styles.css?v=38 ; admin = admin.v32.js + admin.css?v=10. Prochains bumps : admin.css?v=11 (selon fichiers touchés).
- Il existe des copies numérotées : public/app.v5..v52.js, admin/admin.v5..v32.js. TOUJOURS resync toutes quand on change la source.
- **Fourchette de prix (app.v42 / styles.css?v=32)** : si un produit a des `optionPrices` avec prix DIFFÉRENTS selon les options, la carte, la petite modale et la fiche détaillée affichent la fourchette « 15 000 – 18 000 Ar » (`cardPrice` + `renderInitialPrice` + `optionPriceRange`, class `.price.range` compacte 13px nowrap). Avant clic d'option → fourchette ; après clic → prix exact de l'option (`renderOptionPrice`, inchangé). Si tous les prix par option sont identiques → prix unique. Promo (`promoPrice`) = comportement inchangé (l'utilisateur gère le prix promo en admin). **Mobile (styles.css?v=33-34)** : la fourchette reste DANS la ligne du haut avec le bouton compact qui passe juste dessous si pas de place (`flex-wrap`), et le bouton reste ALIGNÉ À DROITE (`margin-left:auto` sur `.add-btn` en <600px) comme sur les prix simples.
- **Pagination boutique (app.v38 / styles.css?v=29)** : grille paginée 18 produits/page (`PAGE_SIZE`), barre `‹ 1 2 3 … ›` (`renderPager()` + `#pager`). Page reset à 1 quand la signature des filtres change (catégorie/sous-cat/facet/recherche/promo/tri). Hash inchangé.
- **Barre nav mobile défilable (styles.css?v=30)** : `.nav` n'est plus masqué sous 860px (était `display:none`) → s'affiche sous le header sticky, défilable gauche/droite déjà géré par `.nav-inner` (overflow-x auto + scrollbar cachée). Cliquer une catégorie = afficher TOUS ses produits (selectCategory 'sub'=''), filtre ensuite via bouton Filtrer/burger.
- **Tri des listes de filtres côté client (app.v46)** : `dimsFor()` renvoie désormais les valeurs **triées** via `sortDimValues(key, list)` (utilisé par le menu burger ET le tiroir « Filtrer ») — `marque` + `saveur` = ordre **alphabétique** français accents ignorés (`localeCompare('fr', {sensitivity:'base'})`), `contenance` = **du plus petit au plus grand volume** (`dimNumber()` : 4 ml → 5 → 10 → 22 → 30 → 50 → 100 → 200 → 1Litre, `L/litre`×1000, `cl`×10), `taux` = **du plus faible au plus fort mg** (`0 mg`, `Sans nicotine`, `10 mg`, `Sel de nicotine 10 mg`, `11 mg`, `12 mg`, `20 mg`, `Sel de nicotine 20 mg`). Une valeur écrite **sans unité** (`20`) est quand même triée comme `20` (fallback `dimNumber`) ; sans aucun chiffre → 0 (en tête). Le tri est **recalculé à chaque rendu** depuis les produits visibles de la catégorie : toute nouvelle marque/saveur/contenance/taux saisie en admin se place automatiquement à sa position (aucune config à faire, il suffit de recharger la boutique). L'admin (dict Réglages) n'est pas trié : seul l'affichage client l'est.

## SEO / Google (sitemap + pages produit)
- **Sitemap dynamique** : `GET /sitemap.xml` (dans `server.js`, `buildSitemap()`) est **généré à la demande depuis `data/products.json`** → il se met à jour tout seul : accueil + **pages catégorie/sous-catégorie** + **tous les produits actifs** (`visible !== false`), y compris les nouveaux ajoutés en admin (aucun redéploiement, cache HTTP 10 min). Chaque entrée produit a son `lastmod` (`createdAt`), `<changefreq>weekly</changefreq>`, `<priority>0.8</priority>` et une entrée **image sitemap** (`<image:image>` avec la photo du produit) pour Google Images. Ne PAS écrire de fichier `sitemap.xml` statique : il deviendrait obsolète.
- **Pages catégorie indexables = LA BOUTIQUE (22/11/2026, app.v50 / server.js)** : `GET /categorie/<slug-cat>` et `/categorie/<slug-cat>/<slug-sous-cat>` (`serveCategoryPage` → **`renderCategorySpaPage`**, slugs via `categorySegment`/`subcategorySegment`/`categoryPath`) renvoie **le HTML de la boutique SPA** (`public/index.html`), pas une page externe : header, nav, recherche, panier, filtres, bannières, footer sont là. Le serveur **injecte** dans ce HTML : `<title>`/meta description/canonical/OG propres à la catégorie, **JSON-LD `BreadcrumbList`**, `<h1 id="sectionTitle">` (au lieu du `<h2>` d'accueil), fil d'Ariane `#ssrCrumbs`, nav + footer « Catégories : … » pré-remplis, et les cartes produit **rendues serveur** dans `#grid` (`.ccard` liées à `/produit/...`, prix/promo/rupture, CSS **scopé** `#grid .ccard` dans `SSR_CATEGORY_CSS` : ne PAS charger `PRODUCT_CSS` ici, il écraserait la boutique). Le JS remplace ensuite ces cartes par la grille SPA (18/page) et garde l'URL propre. `renderCategoryPage()` (ancienne page externe) reste en fallback si `index.html` est illisible. `/categorie/<id>` (ex. `c2`) → **301** vers le slug ; slug inconnu → 404 `noindex` ; HTML en `no-store`. Les catégories/sous-catégories ajoutées en admin apparaissent automatiquement (slug déduit du nom).
- **robots.txt dynamique** : `GET /robots.txt` (`buildRobots()`) → `Allow: /`, `Disallow: /admin`, `/api/`, et ligne `Sitemap: <base>/sitemap.xml`. `siteBase()` déduit l'URL absolue des headers (`x-forwarded-proto`/`host`) ou de `SITE_URL` si défini.
- **Pages produit indexables = LA BOUTIQUE (22/11/2026, app.v52)** : `GET /produit/<slug-du-nom>-<8 premiers car. de l'id>` (`serveProductPage` → **`renderProductSpaPage`**) renvoie le HTML de la boutique avec, injecté côté serveur, le bloc produit (photo + galerie, prix promo barré + `-X%`, stock, marque/contenance/taux, options, description longue `[image]…[/image]` → `<figure>`, bouton WhatsApp), le fil d'Ariane `#ssrProductCrumbs`, `canonical`, Open Graph (`og:type=product`, `og:image`) et **JSON-LD `Product` + `BreadcrumbList`** (prix `MGA`, `InStock`/`OutOfStock`). CSS **scopé** `.ssr-product`/`.sp-*` (`SSR_PRODUCT_CSS`) : ne PAS charger `PRODUCT_CSS`. Côté client, `readProductPath()` (`productSegmentOf()`, même slug que le serveur) retrouve le produit et ouvre automatiquement `openProductDetail()` (ou `openProduct()` si pas de fiche détaillée) **sans changer l'URL** (`writeHash()` garde `/produit/...` tant que `state.onProductPage`) ; `syncProductPage()` cache le bloc serveur et restaure le titre quand on retourne à la boutique. **app.v52** : sur une URL `/produit/...`, `document.body` prend la classe `on-product` → le CSS scopé masque `#hero`, `#trust`, `#products`, `#about` et `.wa-float` (plus de bannières ni de grille de tous les produits sous la fiche, même après fermeture par X) ; `writeHash()` utilise `pushState` quand on quitte une fiche et `onUrlChange()`/`syncProductFromUrl()` réouvrent la fiche au bouton « retour » du navigateur sans écraser l'URL. `renderProductPage()` reste en fallback si `index.html` est illisible. 301 vers le slug canonique et 404 `noindex` conservés ; HTML `no-store`. `productSeo()` doit rester en sync avec `renderProductPage()`. `slugify()` + `productSegment()` sont dupliqués côté client (`public/app.js`) pour que les liens des cartes pointent vers la même URL ; le serveur accepte aussi `/produit/<id>` et redirige en **301** vers l'URL canonique. `/produit/<inconnu>` → 404 `noindex`.
- **URL propre dans la barre d'adresse (app.v49)** : `writeHash()` dans `public/app.js` remplace l'ancien `#cat/c2` par la vraie URL `/categorie/<slug>` (ou `/categorie/<slug>/<slug-sous-cat>`) via `history.replaceState` → **la navigation reste instantanée** (aucun rechargement, filtres/tri/recherche/panier conservés) mais l'adresse affichée est propre et partageable. Les autres filtres (marque, saveur, contenance, taux, promo, recherche) n'ont pas de page dédiée → ils restent en `#…` **mais toujours depuis `/`** (`/#cat/c2/marque/X`, `/#promo`). Depuis app.v50, `readCategoryPath()` (dans `init()`, après `/api/store`) résout aussi les slugs de `location.pathname` → un F5 ou un lien Google `/categorie/...` ouvre **la boutique directement sur la catégorie** (plus de page externe ni de bouton « retour à la boutique ») ; `syncCategoryCrumbs()` garde le fil d'Ariane et le `<title>` synchronisés, et `applyTheme()` n'écrase plus le titre SEO des pages catégorie. `categoryPathOf()` duplique le slug serveur.
- **Liens internes (app.v49 / styles.css?v=38)** : la photo et le nom de chaque carte sont enveloppés dans `<a href="/produit/...">`. Un **clic normal garde la modale** (le handler fait `preventDefault`), mais **Ctrl/Cmd/Shift-clic ou clic-milieu ouvre la vraie page** ; Google suit les `href` → toutes les fiches sont liées depuis l'accueil. Le **footer de la boutique** (`renderFooter()`, classe `.footer-cats`) liste toutes les catégories en liens `/categorie/<slug>` → chaque page catégorie est liée depuis l'accueil. Les pages produit et catégorie ont aussi un footer « Catégories : … » (`footerCats()` dans `server.js`).
- `public/index.html` : `<meta name="robots" content="index, follow">`, `canonical https://vapostoretamatave.com/`, balises Open Graph. L'admin reste `noindex`.
- **Google Search Console** : propriété `vapostoretamatave.com` (propriété de domaine via DNS = couvre http/https + www), puis Sitemaps → `https://vapostoretamatave.com/sitemap.xml`. Le sitemap est aussi accessible via `https://vapo-store.onrender.com/sitemap.xml` mais il déclare les URLs en `.com` → toujours soumettre la version `.com`.

## Structure
- `server.js` : tout le backend (API, fichiers statiques, auth). `handleApi()`, `normalizeProduct()`, `serveStatic()`.
- `public/` : boutique (index.html, app.js = renderFooter/renderHero/etc., styles.css, images/, uploads/).
- `admin/` : panel admin (index.html, admin.js, admin.css).
- `data/` : produits, commandes, catégories, bannières, réglages, dict. Modifiés au runtime.
- `render.yaml` : blueprint Render (service + disque `/data`).
- `.gitignore` : node_modules + fichiers OS.

## Base de données = fichiers JSON dans data/
- `products.json`, `orders.json`, `categories.json`, `banners.json`, `settings.json`, `dict.json`.
- `dict.json` : saveurs/marques/contenances/taux. **Les nouvelles marques/saveurs/contenances créées dans un produit s'auto-enregistrent** dans dict (côté serveur `addToDict()`).

## Déploiement (EN LIGNE)
- **Repo GitHub** : `https://github.com/Vapostoretamatave/vapo-store.git` (branche `main`).
- **Site officiel : https://vapostoretamatave.com** (domaine perso branché sur le service Render ; `www.` et `http://` redirigent en 301 vers `https://vapostoretamatave.com`). URL technique : `https://vapo-store.onrender.com` (même app, forfait Starter, disque persistant 1 Go monté sur `/data`).
- ⚠️ **Toutes les URLs canoniques** (sitemap, robots.txt, `canonical`, Open Graph, JSON-LD) utilisent le domaine `.com` : constante `PRIMARY_SITE` en haut de `server.js` (+ `siteBase()` qui force le `.com` quand on passe par `*.onrender.com` ou `www.`). En local, `siteBase()` renvoie `http://localhost:3000`. Si le domaine change : modifier `PRIMARY_SITE`, ou définir la variable d'env `SITE_URL` (prioritaire).
- Mise à jour : `git add .` → `git commit` → `git push origin main` → Render redéploie automatiquement en ~2-3 min.
- ⚠️ **502 pendant ~10 s à chaque « création de fiche » = coupure due au REDEPLOY, pas à l'API** : le service a un **disque persistant `/data`**, et la doc Render dit explicitement qu'un disque persistant **désactive le zero-downtime** (« *Adding a persistent disk to your service disables zero-downtime deploys* »). Donc **tout push sur `main` coupe le site quelques secondes** (ancienne instance arrêtée avant que la nouvelle soit prête). Quand on ajoute une fiche via l'API + qu'on commit `AGENTS.md` juste après, l'utilisateur voit un 502 de 10 s et croit que c'est la création. **Règle : pour les mises à jour de mémoire / docs seules (et tout commit qui ne change pas le code servi), utiliser un message avec `[skip render]`**, ex. `git commit -m "[skip render] docs: ajout fiche ..."` → Render ignore le commit (aucun déploiement, aucune coupure). Les phrases acceptées : `[skip render]`, `[render skip]`, `[skip deploy]`, `[skip cd]`. Continuer à pousser **sans** skip phrase uniquement pour les vraies modifs de code (`server.js`, `public/app.js` + versions numérotées, CSS + bump `?v=`, `admin/*`, `render.yaml`). Alternative plus propre à configurer dans le Dashboard Render : *Settings → Auto-Deploy* ou **Build filters** (ne déployer que si `server.js`/`public/`/`admin/` changent).
- ⚠️ **Workflow DONNÉES** : les produits se créent/modifient depuis l'ADMIN EN LIGNE (instantané, rupture de stock/prix). Git ne sert QUE pour le code. Le disque (/data) est la source de vérité et le redéploiement ne l'écrase jamais.
- **Variables d'env en prod** : `DATA_DIR=/data`, `UPLOAD_DIR=/data/uploads`.
- Servir fichier : `DATA_DIR`/`UPLOAD_DIR` sont lus depuis l'env en prod, local sinon (voir début de server.js : **LE DISQUE (/data) EST LA SOURCE DE VÉRITÉ des données**. L'admin EN LIGNE écrit directement dessus (produits, commandes, catégories, bannières, réglages, images). `syncCatalogToDisk()` ne copie `data/` + `public/uploads/` → disque QUE si `settings.json` absent (1er boot d'un disque neuf). Ensuite le redéploiement ne touche JAMAIS au disque → les modifs en ligne ne sont jamais écrasées. ⚠️ **Ne PAS modifier les produits en LOCAL et les pousser** : git = code seulement. Sauvegarde : admin en ligne → Réglages → « 💾 Télécharger la sauvegarde » (`GET /api/admin/backup` : JSON avec produits+commandes+settings+images base64) → à conserver sur Google Drive.
- Git exécutable : `C:\Program Files\Git\cmd\git.exe` (pas dans le PATH de la session opencode actuelle).
- Structure des prix Render : Starter ≈ 7$/mois (Web Service) + disque 0,25$/Go/mois. Free = pas de disque (données perdues au restart) + mise en veille après 15 min.
